Agent（智能体）

2. 核心问题

  1. 同样是大模型驱动的系统，凭什么有的叫"工作流"，有的叫"Agent"？分界线画在哪？
  2. Agent 是靠什么"自己拿主意"的？它的决策循环长什么样？
  3. 什么时候不应该用 Agent？

3. 我的理解（个人解释）

我是这样理解的：普通的大模型对话像问路——你问一句，它答一句，具体怎么走还是你自己的事；而 Agent 像你雇的一位司机——你只说"送我去机场"，它自己看导航、选路线、遇到堵路会绕行，到了地方还告诉你"到了"。

关键差别在于谁掌握流程控制权。Anthropic 在《Building Effective Agents》里给了一条我特别认同的分界线：如果大模型的每一步都被代码预先安排好（第一步干什么、第二步干什么都写死了），那是 Workflow（工作流），大模型只是流水线上的工人；如果大模型自己动态决定下一步调用什么工具、什么时候算干完了，那才是 Agent。所以 Agent 的本质不是"更聪明"，而是"更自主"——自主权从开发者手里移交给了模型。

还有一点我原来想错了：我以为 Agent 一定很复杂、要上多智能体框架。实际上 Anthropic 的建议恰恰相反——能用简单方案就别上 Agent。Agent 是拿延迟和成本换灵活性，任务路径能预先想清楚的就该用 Workflow，甚至单次 LLM 调用就够了。

4. 核心机制 / 组成

一个典型 Agent 由四部分组成：

组成作用类比
LLM（大脑）负责理解目标、推理规划、决定下一步动作司机的脑子
工具（Tools）搜索、读写文件、执行代码、调用 API 等实际行动能力车 + 导航仪
决策循环（Agent Loop）"思考 → 行动 → 观察结果 → 再思考"的循环，直到模型判断任务完成边开边看路况
上下文 / 记忆装载目标、历史操作和中间结果的"工作记忆"司机对这一趟行程的记忆

决策循环是 Agent 的心脏，大致长这样：

接收目标 → [思考：还差什么？] → 调用工具 → [观察：结果如何？] → 未完成？回到思考 → 完成 → 汇报结果

注：Anthropic 把 LLM + 检索 + 工具 + 记忆的增强单元称为 "augmented LLM"（增强型 LLM），它是所有 agentic 系统的基本构件；Workflow 和 Agent 都是围绕它搭建的。

5. 具体应用场景

场景：用 WorkBuddy 整理一份课程作业仓库。

我这次作业就是一个真实例子：我说"帮我完成这份作业"，Agent（WorkBuddy）自己拆解出一系列步骤——检查 gh CLI 登录状态 → 创建 GitHub 仓库 → 克隆到本地 → 写 SKILL.md → 联网核实资料来源 → 生成学习资料 → git 提交推送。这些步骤没有一个是我预先写死的流程，它边干边决定下一步（比如发现已登录 gh 就直接建仓库）。对比之下，如果用 Workflow 做，我需要预先定义好每个步骤，换个作业题目就得重写流程。

反面判断：如果任务固定不变——比如"每天早上 8 点把昨天的销售数据汇总成一张表"，步骤完全可枚举，那就该用 Workflow（定时脚本 + 固定流水线），更稳定、更便宜、更好调试。

6. 概念辨析（易混淆点与边界）

易混淆项区别边界：什么时候不是 Agent
Agent vs Chatbot Chatbot 只生成文本回复，不采取行动；Agent 会调用工具、对环境产生实际影响 只会聊天、什么文件都不改、什么工具都不调的，只是对话应用
Agent vs Workflow Workflow 的流程控制权在代码（路径预定义）；Agent 的控制权在大模型（路径动态决定） 只要"下一步做什么"是代码写死的，无论叠多少个 LLM 调用，都只是 Workflow
Agent vs 机器人流程自动化（RPA） RPA 按脚本精确模拟人的界面操作，无理解能力；Agent 用 LLM 理解意图后自主行动 如果系统只是机械重复录制的操作、遇到意外就报错，那是 RPA 不是 Agent

使用边界（重要）：Anthropic 的工程建议是——从最简单的方案开始：单次 LLM 调用 → 检索/示例增强 → Workflow → 最后才是 Agent。任务路径无法预先想清楚、需要模型临场判断的开放性任务，才值得用 Agent。

7. 自测问题

Q1：某系统按固定顺序调用了 5 次大模型，每次处理上一步的输出。它是 Agent 吗？

参考答案：不是。这是典型的 Workflow（提示链 / prompt chaining）。虽然它多次调用 LLM，但每一步由代码预先安排，LLM 没有掌握流程控制权，不能自主决定下一步做什么、何时结束。

Q2：Agent "自主性"的技术来源是什么？

参考答案：决策循环（agent loop）：模型在"思考 → 调用工具 → 观察结果"的循环中自己决定下一步调用哪个工具、是否继续，直到它判断任务完成。控制权在模型而非预写代码。

Q3：列出 Agent 相比 Workflow 的两个代价。

参考答案：① 不确定性高（同样的任务可能走出不同路径，出错路径难以复现和调试）；② 成本与延迟更高（多轮工具调用、多轮 LLM 推理，Token 消耗显著增加）。

Q4：为什么"多智能体框架"不等于 Agent？

参考答案：框架只是实现工具。用重型框架搭出来的系统如果流程都是预定义的，本质仍是 Workflow；反过来，几十行代码直连 LLM API，只要让模型自主决定工具调用，就是 Agent。判断标准是控制权归属，不是用了什么框架。

Q5：你的任务"每天汇总销售数据发邮件"该用什么方案？为什么？

参考答案：Workflow（甚至定时脚本 + 单次 LLM 调用）。任务步骤完全可枚举、路径可预先定义，Workflow 更可预测、更易测试、成本更低。只有在任务路径无法预先想清楚时才需要 Agent。
