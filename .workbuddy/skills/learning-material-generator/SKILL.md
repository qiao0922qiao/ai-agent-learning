# 概念学习资料生成器（learning-material-generator）

把"学一个新概念"变成一条可复用的流水线：输入概念名，输出一份自己能看懂、能复习、能核查的学习资料。

## 适用场景

- 学到一个新概念（如 Agent、上下文、RAG、微调、MCP……），想系统整理成笔记
- 课程作业需要为若干概念生成结构化学习资料
- 复习旧概念时，想要一份带自测题的速查材料
- **不适用**：需要完整教程/动手实验的主题（本 Skill 聚焦"单个概念的理解与辨析"，不生成实操指南）

## 输入信息

调用本 Skill 时，用户需提供：

| 输入项 | 必填 | 说明 | 示例 |
|---|---|---|---|
| 概念名称 | ✅ | 要学习的概念 | "大模型的上下文" |
| 背景说明 | ❌ | 为什么学、学到什么程度 | "课程作业，需要能向同学讲清楚" |
| 已有理解 | ❌ | 用户当前的认知水平，用于生成"个人解释"的起点 | "我只知道上下文有长度限制" |

若用户只给了概念名，其余项按"初学者、希望能用自己的话复述"的默认假设处理，并在资料中注明该假设。

## 生成步骤

按顺序执行，不得跳步：

1. **理解概念定位**：先用 1–2 句话确定概念属于什么领域、解决什么问题。如果概念有歧义（如 "Agent" 在 AI 领域和其他领域含义不同），先和用户确认，或按 AI 领域默认解释并明确注明。
2. **联网核实来源（必须）**：使用联网搜索查找 2–4 个权威、可公开访问的资料来源（官方文档、官方博客、知名技术作者的长文）。**必须实际搜索验证链接真实可访问，禁止凭记忆编造 URL 或来源名称。** 优先级：官方文档 > 官方工程博客 > 高校/知名研究者文章 > 高质量技术社区文章。
3. **组织学习框架**：按下述"输出结构"确定资料的小节，并为这个概念定制：
   - 3–5 条可检验的学习目标（用"能……"句式）
   - 3 个核心问题（学完资料应能回答）
   - 2–3 组易混淆概念的对比点
   - 4–6 道单选题（每题 4 个选项，其中 1 个正确；干扰项要合理、对应常见误解；正确答案附解析，解析要说明"为什么"并纠正对应误解）
4. **撰写内容**：
   - "个人解释"小节用第一人称、口语化的类比来写，禁止整段照搬任何来源原文或 AI 对话原文；每份资料至少包含一个原创类比
   - "核心机制"小节按组成/流程拆解，可用列表或简单示意
   - "应用场景"小节必须具体到一个可想象的真实任务，不写空泛的"广泛应用于……"
5. **生成 HTML 文件**：单文件 HTML（样式内联，不依赖外部 CDN），UTF-8 编码，浅色主题，统一视觉模板：渐变色页头（含概念名、一句话定位、元信息胶囊）→ **"30 秒速懂"板块（黄底提示框：一句话定义 + 一个生活化例子，让读者不读正文也能立刻建立直觉）** → 吸顶目录导航 → 编号小节卡片。自测部分做成**交互式单选题**：点击选项即时判分（正确绿色/错误红色并标出正确项），下方展开解析，顶部显示"已作答 X/N ｜ 答对 Y"计分条并提供"重新作答"按钮（内联 JavaScript 实现，不用外部库）。保存到仓库的 `learning-materials/` 目录，文件名用概念的英文小写短横线命名（如 `agent.html`、`llm-context.html`）。
6. **自检**：执行下方"自检要求"清单，不通过则修改后重新自检。
7. **报告**：向用户汇报生成的文件路径、核实过的来源列表，并提醒用户阅读和修改"个人解释"小节（那应该是用户自己的话）。

## 输出结构

每份学习资料的 HTML 包含以下小节（顺序固定）：

```
1. 页头：概念名 + 一句话定位 + 元信息（生成日期、概念领域）
2. 30 秒速懂：一句话定义 + 一个生活化例子（先建立直觉，再读正文）
3. 学习目标：3–5 条，"能……"句式
4. 核心问题：3 个，学完应能回答
5. 我的理解：第一人称的个人化解释，含至少一个原创类比
6. 核心机制 / 组成：概念的构成要素或工作流程
7. 具体应用场景：一个具体的真实任务场景
8. 概念辨析：2–3 组易混淆点，含"什么时候不是这个概念"的边界说明
9. 自测问题：4–6 道交互式单选题，点击选项即时判分并展开解析，支持计分与重新作答
10. 参考来源：2–4 个已核实的链接，每个附一句话说明"这个来源讲清楚了什么"
```

## 资料来源要求

- **真实性**：所有来源链接必须经联网搜索核实真实存在且可访问，禁止编造
- **可访问性（重要）**：提交前必须实际访问每个链接并确认返回的是正文内容而非错误页；部分官方文档站点存在区域访问限制（如跳转到"App unavailable in region"页面），此时应改用同一来源的可访问版本（如官方工程博客、镜像文档），不得保留打不开的链接
- **权威性**：优先官方文档/官方工程博客；不得引用无法追溯到原始出处的二手转载
- **多样性**：至少包含两个不同来源，避免单一来源决定全部理解
- **标注方式**：每个来源附一句话说明其价值（"这篇讲清楚了 workflow 和 agent 的区别"）
- **时效性**：优先近两年的资料；若用了较老的资料，注明发表时间

## 自检要求

生成资料后，逐项核对，全部通过才算完成：

- [ ] 所有参考来源链接均经过联网核实，且**实际访问确认返回正文内容**（非错误页/区域限制页）
- [ ] 页首有"30 秒速懂"板块：一句话定义 + 生活化例子，无术语堆砌
- [ ] "我的理解"是个人化的解释，没有整段照搬来源或 AI 对话
- [ ] 每个概念辨析点都说明了"边界"（什么情况下不是这个概念）
- [ ] 自测单选题的正确答案与解析、正文内容三者一致，干扰项对应真实存在的常见误解
- [ ] HTML 无外部依赖，直接双击可在浏览器打开
- [ ] 已提醒用户人工阅读、修改"我的理解"部分
